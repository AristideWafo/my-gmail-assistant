# Instructions projet

- Pas de commentaires superflus dans le code. Commenter seulement le POURQUOI non-évident (contrainte cachée, workaround, invariant subtil) — jamais le QUOI.
- Bien structurer le code : modules/fonctions clairs, responsabilités séparées.
- Privilégier le code réutilisable : éviter la duplication, factoriser sans sur-abstraction prématurée.
- Toujours inclure des tests unitaires pour le code ajouté ou modifié.
- Toujours planifier les grosses tâches avant implémentation (utiliser le mode Plan) avant de coder.
